# Validation-18 执行规范

本规范汇总已接受的建设要求。评分以同版本的 SCORE_RULES.md v3.4.1 为准；原 REAL_REPOSITORY_GUIDANCE.md 是历史档案，不作为自动执行指令。原文中的统计、未裁定建议和旧评分表不覆盖本规范。

## 目标与范围

- 保留 v0.8.0 作为真实源码 Dev/Regression 基线；原 18 仓 HEAD、旧标签和分数不改写。
- 维护现有 9 APP + 9 Android Framework；22 pending 不开启，MATLAB 独立维护。
- 另建少量微型边界对照供检验评分行为。对照不是生产体量样本，不混入 18 仓分母；同源变体共享 family_id，不跨调参/独立验证拆分。
- 不以质量角色反推分数，不因缺少某一档就改现有标准答案，不以填充代码扩大体量。

## 源码与生产范围

每仓绑定精确 commit/tree/refs。按真实 Gradle sourceSets/变体、Soong srcs/defaults/filegroup/消费者链、Android Make/CMake 目标确定生产路径；src/main 只是示例。记录完整路径集合、逐文件行数、构建归属、排除理由和未决项。

生产代码行去除注释、空白及明确生成区域。资源、构建脚本、测试、第三方代码不计体量；它们仍可在需要时作为权限、依赖、构建、测试或风险证据。Test/Mock 名称不单独决定排除。

APP 的 small/medium/large 分界为 30K/80K，FW 为 80K/200K；文件数仅作画像。不能确定归属的路径必须公开 unresolved，不得默默丢弃以换取高分。

## 评分与证据

- APP 8 叶/40；FW 11 叶/52，共 171 叶/828。维度、档位、执行证明和模块命名门槛本轮不变。
- 先提取/观察事实，再独立应用合同，最后比较既有答案。错误按具体证据裁决，不平均或投票。
- 代码证据给 path/line/symbol/commit；分支证据给真实 tip/tree 和生效配置/代码差异。只改名称、只加 Adapter 或只堆 API 次数均不足以证明档位。
- 公开区分确定性路径/计数、人工语义观察和档位映射。重放成功不等于语义判断自动成立；抽样外的行为不宣称已经穷尽。
- 测试 2/3 分必须满足合同的 final-HEAD 实际执行、通过率和可复算关键交互覆盖要求，不得把微型 host 检查冒充全仓集成覆盖、把 host 执行冒充设备执行，或以源码测试数/目录存在替代执行。

## 交付与恢复

源码输入与维护者工具/答案分开。维护者验证资料应包含完整生产路径、排除清单、逐文件计数、构建锚点、实际观察输入、语义裁决和可运行重放入口，不要求外部访问本地 staging。

恢复结果分别报告主仓源码评审就绪、gitlink 固定提交的子模块就绪、完整构建环境及实际构建执行状态。下载子模块不证明 SDK、Maven、平台树或设备环境完整；第三方依赖不进入自有代码体量。

## 对照与评测

先发布“类型×叶×档位×证据状态”覆盖表及样本内众数基线。优先构造有真实行为差异的发布策略、平台隔离/降级对照；FW CI 和 Android 集成正例必须有实际执行支持后才计入覆盖。

对照先作为候选小样交付，附可运行行为检查和源码证据；未经独立裁决不冒充完整 canonical gold。比较 Prompt 时同时看逐叶逐档表现、证据正确性、失败/弃权、重复运行波动及成本。当前公开集不宣称独立最终 holdout。

当前另有8条已裁定边界回归叶，按 BOUNDARY_REGRESSION.md 单独报告。证据模式及可比性采用 EVIDENCE_PROTOCOL.md；集成测试严格遵循现行合同3.5，允许具备实际接口范围与执行覆盖的JUnit/Robolectric/native测试，运行环境分别标明。本轮不改变API档位口径。
