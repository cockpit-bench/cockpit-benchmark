## 可直接交给网页版 Reviewer 的要求

请只读审阅此 wrapper 及 manifest 中的 18 个公开源码仓，检查真实仓库形态与标准答案是否一致。

1. 完整阅读本页、指导原文与 SCORE_RULES.md，区分原文建议、后续取舍、现行合同与当前源码事实。
2. 从 manifest 的精确 HEAD 查看源码及构建入口。检查业务职责是否完整连贯，生产计数是否有真实构建归属，有无复制、空壳、不可达代码或资源/测试凑体量；检查功能域及上游谱系多样性，不能只看仓名。
3. 按合同独立判断各叶，再与 facts/oracle/标准分对照。逐项指出证据不足、分档错误、平台风险漏判、SOLID 行为判断冲突；不要以 high/medium/low 标签反推分数。
4. 分开报告静态可见入口、实际构建执行、实际测试执行和覆盖范围。测试文件存在不等于测试通过；定向 JVM/Metalava 检查不等于完整 Android 构建或设备集成测试。
5. 对原指导条目分别标记：有源码证据支持、存在差距、与现行合同冲突不适用、缺原始数据无法判断。不要把来源摘要的边际频率当作每仓配额或真实联合分布。
6. 每个问题给出仓 ID、精确 commit、path/line/symbol（或 ref）、对应合同/指导条款、具体影响与最小建议。无法访问源码、历史 refs 或执行环境时列明缺失证据，不编造完成状态。

本轮已有 171 叶零差异重算和 18/18 匿名完整恢复记录，见 [v0.8.0 Release](https://github.com/cockpit-bench/cockpit-benchmark/releases/tag/v0.8.0)；这些是已有验证声明，不能替代 reviewer 的独立源码核查。全部仓完整 Android 平台编译/设备集成测试尚未执行。质量角色为类型/体量组内相对覆盖，套件用于 Dev/Regression，不宣称独立谱系的最终 holdout。

本页包含标准答案入口，只用于维护者 review；盲评输入应仅提供单个源码仓，不附带 wrapper、指导或答案。
