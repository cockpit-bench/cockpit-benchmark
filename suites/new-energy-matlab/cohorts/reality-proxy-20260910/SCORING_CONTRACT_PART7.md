## 评分标准

- **0分** - 无分支策略：无计划的分支管理，分支零散无规律
- **3分** - 单车型单分支：一个车型一个分支，分支名以车型代号区分
- **8分** - 同平台同一分支：一个平台一个分支，分支名以平台代号区分，同平台不同车型共用分支
- **10分** - 跨平台同一分支：分支合一，所有平台共用同一分支，通过配置或变体实现差异化

## 分析要求

本维度通过分析 Git 分支策略和分支名来确定 release 分支策略。预处理脚本提取以下信息：
1. **分支列表** — 所有远程分支名称
2. **分支名中的平台代号** — 检测是否包含已知平台代号（E04、E06、XCU、XCU1、XCU2、XCUP）
3. **分支名中的车型代号** — 检测是否包含车型代号模式（字母+3位数字，如 L743、P171、E171）
4. **分支统计** — 含平台代号的分支数、含车型代号的分支数、都不含的分支数
5. **分支策略判定提示** — 脚本根据分支名模式给出的初步判断

**分析逻辑：**
- 分支数 ≤ 1 或分支无规律 → 偏向 0 分（无分支策略）
- 分支名大量含车型代号（如 L743、P171）→ 偏向 3 分（单车型单SOP分支）

- 分支少且不含平台/车型代号 → 偏向 10 分（跨平台同一分支，分支合一）
- 分支策略不明确时，需人工进一步判断

# 层次分解评分 Prompt

请分析这个Simulink模型的层次分解情况，严格按照以下评分标准进行评估：

## 评分标准

- **0分** - 无层次：模型缺乏层次结构，无子系统划分，所有块平铺在同一层级
- **1分** - 粗糙划分：存在子系统划分，但粒度划分不均（部分子系统包含大量块，部分仅含极少块），职责边界不清晰
- **2分** - 基本清晰：层次划分较为清晰，粒度较均匀，职责基本清晰，但个别子系统职责可能不够单一
- **3分** - 清晰规范：层次划分清晰，每层抽象粒度一致，≥90% 的子系统有明确且单一的职责

## 分析要求

请基于预处理脚本输出的 JSON 结果中的 `hierarchy` 部分进行分析，重点检查以下方面：

### 1. 层次结构分析

- 统计模型的总层次深度（嵌套层数）
- 统计每一层的子系统数量
- 识别是否存在过深嵌套（一般建议不超过 3-4 层）或过浅结构

### 2. 粒度均匀性分析

- 统计每个子系统直接包含的子块数量（不含更深层级的块）

- 检查是否存在职责重叠的子系统（名称或内容相近、功能交叉）
- 评估每个子系统是否符合单一职责原则：即一个子系统只完成一项明确的功能，而非混合多个功能

### 4. 整体架构评估

- 顶层子系统的划分是否覆盖了模型的主要功能域
- 层次间是否存在不必要的耦合（如跨层级直接引用）
