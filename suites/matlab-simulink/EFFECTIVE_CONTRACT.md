# MATLAB/Simulink 当前有效评分合同

候选执行入口。由冻结原文与已批准裁定合成；只含 13 叶，满分 61，独立于 Android。
从高档向低档匹配；不插值、不平均、不按目标角色倒推。证据不足标 failed，不编造数字。
真实行为、连线与断言是事实基础；静态解析、模型加载/更新、仿真、代码生成、编译及 SIL/PIL/HIL 分别报告，不能相互替代。
源码、版本与证据必须绑定；计数与文件存在性不能代替职责、命名、复用或准确性的语义判断。

每叶输出 id、status、score、理由、具体证据及审阅范围；failed 的 score 为 null。证据标明仓库 HEAD、路径、行段/模型元素和支持的事实。

## 2.1 层次分解 (`hierarchy`)

满分 3；合法分值：0/1/2/3。

- 0＝无层次：模型缺乏层次结构，无子系统划分，所有块平铺在同一层级
- 1＝粗糙划分：存在子系统划分，但粒度不均，职责边界不清晰
- 2＝基本清晰：层次划分较清晰，粒度较均匀，职责基本清晰
- 3＝清晰规范：每层抽象粒度一致，≥90% 子系统有明确且单一职责

审阅事实：SubSystem 父子嵌套树、总层次深度、每层子系统数、每子系统直接子块数(粒度均匀性)、巨型/微型子系统、子系统命名职责清晰度、Model Reference/Library Link 功能分离

## 2.2 复用与标准化 (`reuse`)

满分 3；合法分值：0/1/2/3。

- 0＝全手工搭建：未用内置库模块，无可复用设计
- 1＝有重复：用了内置库基础模块，但存在同一逻辑模块多处副本
- 2＝已封装无重复：可复用模块已封装，未被重复实现
- 3＝优秀封装：封装优秀，隐藏细节暴露参数，均通过 Library Link/Model Reference 使用

审阅事实：内置库块(Sum/Gain/Product/Switch)、重复逻辑(同名/同块组合子系统)、Mask 参数、暴露可调参数、Atomic Subsystem、LibraryLink/SourceLibrary、Model Reference、自定义库.slx

## 2.3 接口设计 (`interface`)

满分 3；合法分值：0/1/2/3。

- 0＝隐式通信：依赖 Goto/From/DataStore 等隐式机制
- 1＝显式接口：用 Inport/Outport，但定义不完整或命名不规范
- 2＝完整清晰：接口完整清晰，端口命名规范
- 3＝规范约束：有受控变更管理 + 数据类型/单位/取值范围完整描述

审阅事实：Goto/From 计数与占比、DataStoreRead/Write、Inport/Outport、端口命名(默认 In1/Out1 vs 语义)、端口数据类型、物理单位、接口变更管理文档

范围：全部生产根模型公开 Inport/Outport、跨模型依赖及影响公开边界的 Goto/From/DataStore。完整性、命名、类型、单位、范围、受控变更均使用同一范围。内部子系统仍纳入层次分解、数据流及命名审阅。

## 2.4 数据流与信号路由 (`dataflow`)

满分 3；合法分值：0/1/2/3。

- 0＝混乱：大量未命名信号和隐式跳转
- 1＝部分命名：部分关键信号有命名，走线交叉或跳转过多
- 2＝基本清晰：关键信号语义化命名，较少交叉跳转
- 3＝清晰一致：命名清晰，流向一致，仅必要交叉/跳转

审阅事实：已命名 vs 未命名信号占比、Goto/From 使用计数、Mux/Demux、BusCreator/Selector、信号分支数、命名质量(语义 vs s1/s2)、跳转合理性

## 2.5 单元测试 (`unit_test`)

满分 5；合法分值：0/1/3/5。

- 0＝无单元测试或测试用例无效
- 1＝有单元测试，测试用例有效，测试方法得当
- 3＝有单元测试，单元测试目标明确，测试预期合理，大部分通过，且覆盖率≥50%
- 5＝以上均达到，测试全部通过，且覆盖率≥80%

覆盖率专指 decision coverage；多生产模型按 covered/total 目标数汇总，不平均百分比。排除 harness，复用定义去重，显式记录过滤。无 decision 目标不自动算 100%。有效测试无覆盖证据可得 1；无 BTC 文件名不直接判 0，真实 Simulink 报告可用。

审阅测试输入、预期、方法、断言、通过率、绑定版本的真实报告及覆盖目标分子/分母。

## 2.6 命名规范 (`naming`)

满分 5；合法分值：0/1/3/5。

- 0＝难以通过命名理解意图（大量默认名或无意义命名）
- 1＝部分命名有意义（仍有较多默认/随意）
- 3＝命名基本能反映功能/含义，风格统一（个别不精确）
- 5＝各类型模型元素命名准确传达意图和层级关系，风格高度统一（≥90% 准确）

审阅事实：Subsystem 默认名、Inport 默认名(In1)、Outport 默认名(Out1)、信号空/自动名(s1/s2)、基础块默认名、Constant 默认名、MATLABFunction 默认名、Stateflow 默认名、ModelRef 默认名、Bus 块默认名、观测块(Scope/Display)默认名、风格一致性

## 2.7 目录结构 (`directory`)

满分 5；合法分值：0/1/3/5。

- 0＝文件未按目录分类管理（平铺根目录）
- 1＝部分文件按目录分类管理（划分不完整/不一致）
- 3＝目录划分基本合理，命名基本清晰
- 5＝目录划分清晰，命名可读性高，无职责交叉

审阅事实：顶层目录类别、跨职责文件/目录、根目录未分类文件、目录命名清晰度、目录内细分

## 2.8 构建独立性 (`build_independence`)

满分 3；合法分值：0/1/2/3。

- 0＝存在未受控的仓外业务源码依赖，构建需加载对方源码。
- 1＝仓外业务依赖仅以预编译或保护模型交付，未满足更高档。
- 2＝仓外业务依赖采用带端口、Bus、Mask 参数的接口化可复用组件，未满足 3 分。
- 3＝无仓外业务依赖；或仓外依赖为版本管理、发布基线及版本锁定引用的稳定组件库。

以仓库为边界；同仓源码、预编译、保护模型依赖均属正常模块化。MATLAB/Simulink 基础工具环境单列，不算外部业务依赖。高档优先，版本化接口组件采用源码交付不覆盖其高档条件；实际构建成功与评分分别报告。

## 2.9 模型版本管理 (`model_version`)

满分 3；合法分值：0/1/2/3。

- 0＝无记录：无变更记录和版本标记
- 1＝部分记录：部分有记录，不完整/散落
- 2＝较规范：规范记录主要变更，含版本号/日期/内容
- 3＝正式完整：完整记录含变更对比/版本标记/变更说明/信号量变更

审阅事实：模型变更记录文件(PPT/Excel/文本)、接口变更记录、记录含版本号、变更日期、变更描述、前后对比、信号增减、记录连续性、记录规范化、模型与接口记录交叉引用

## 2.10 版本独立性 (`version_independence`)

满分 3；合法分值：0/1/2/3。

- 0＝无版本号
- 1＝内部版本号：仅内部序号/构建号
- 2＝独立版本号：有正式版本号，但不遵循语义化
- 3＝语义化版本号：MAJOR.MINOR.PATCH 三段式

审阅事实：版本号(文档/记录/模型属性/README/配置)、版本来源位置、是否独立版本、是否语义化(X.Y.Z)、版本格式、版本历史、git 语义化 tag

语义化三段附 build 标记（例如 11.x.x_0 的实际数字版本）仍可符合 3 分。

## 2.11 release代码分支策略 (`release_branches`)

满分 10；合法分值：0/3/8/10。

- 0＝无分支策略（无计划）：分支零散无规律
- 3＝单车型单SOP分支（一个车型一个分支）
- 8＝同平台同一分支（一个平台一个分支）
- 10＝跨平台同一分支（分支合一，配置/变体实现差异化）

审阅事实：远程分支全量、分支名平台代号(E04/XCU1/XCUP)、分支名车型代号(L743/P171)、分支统计(含平台/含车型/都无)、分支名模式推断策略

单一主分支通过配置支持多个平台可得 10，不以分支数≤1判 0。按统一主线、平台分支、车型分支或无计划策略裁定。可使用已接受的分支命名近似，不新增跨平台执行门禁。记录型号 token 及角色，任意字母数字串不自动视为车型；auto 分支追踪来源。

## 2.12 设备特有 (`device_specificity`)

满分 10；合法分值：0/3/8/10。

- 0＝高度定制，只为单车辆使用（分支名强耦合特定车型代号）
- 3＝轻度定制，为某系车型开发（分支名含车型代号但不限于单车）
- 8＝通用软件，但需通过硬编码实现差异化需求（跨车型但硬编码差异化）
- 10＝通用软件，不受平台设备制约，可以全平台应用（分支名无特定代号）

审阅事实：远程分支全量、分支名平台代号、分支名车型代号、分支统计、设备定制推断

本轮接受分支名近似：无车型或平台代号可认定设备通用，得 10。与 release 共用一次分支事实；记录明确识别的 token/角色及 auto 分支来源。不新增 N/A 出口或跨平台执行门禁；该近似不代表实际全平台验证。

## 2.13 参数管理 (`parameter_management`)

满分 5；合法分值：0/1/3/5。

- 0＝大量业务数值硬编码，未参数化。
- 1＝部分关键参数变量化，但多数仍散落、未集中。
- 3＝全部可调参数变量化且集中，分类结构清晰，尚未满足 5 分的集中且准确并实际使用要求。
- 5＝所有应管理的业务参数集中、准确且实际被模型使用。

参数不限形式、位置或扩展名。核对所有应管理业务参数的集中性、准确性及实际消费者；准确性包括值、类型、单位适配与记录一致。模型工作区、脚本、字典、接口表均可。类型、范围和变更记录保留事实，但不是额外的 5 分门槛。

## 统一边界

不评价 CI 独立性、版本策略、发布与回滚、平台升级影响、单平台或跨平台代码复用率六个排除维度。
D01—D15 只作为检查线索，不自动决定分数；无某扩展名、指定目录名或指定报告名不能替代实质判断。
生产范围包含全部有效模型实现；harness、停用块、生成码与无业务填充不算生产规模。仓内库和引用模型定义去重；供应商库内部实现不展开凑数。
规模以有效生产逻辑块计：1–199 小型、200–799 中型、≥800 大型；纯接口/路由/显示及容器不计。规模角色不决定任何叶分。
